## 踩坑记录
- starlette 0.50.0：`receive_bytes()` 遇到文本帧会 KeyError（消息里没有 `bytes` 键），
  需改用 `receive()` 并自行处理 `websocket.disconnect`（`receive()` 不会抛 `WebSocketDisconnect`）。
- 流式 VAD 输出的是**边界事件** `[beg,-1]`/`[-1,end]`，坐标均为相对流起点的毫秒；
  孤立的结束事件若不丢弃，会残留 `last_vad_end` 污染下一片段（对空音频推理）。
- `offset` 应与缓冲区起点严格一致（用实际裁掉的样本数换算），不要直接用 VAD 声明的毫秒推进。
- 本项目 `requirements.txt` 是 UTF-16 编码。

## 实测确认的错误响应行为（写文档前逐一探测过，勿凭直觉）

| 场景 | 状态码 | 响应体 |
|---|---|---|
| 缺/错 `apiKey`（HTTP） | 403 | `{"detail": "Invalid or missing API key. Please provide apiKey parameter."}` |
| 不支持的音频格式 | 400 | `{"detail": "Unsupported audio format"}` |
| 缺 `file` 字段 | 422 | `{"detail": [{"type":"missing",...}]}` |
| 推理等未捕获异常 | **200** | `{"code":1,"info":"<异常信息>","data":"","sentences":[]}` |
| WS 缺/错 `apiKey` | — | 关闭码 `1008`，reason `Invalid or missing API key` |
| WS 说话人命中 | — | `{"code":2,"info":"speaker","data":"<注册音频URL>","sentences":[]}` |

**关键结论**：`@app.exception_handler(Exception)` 的**自定义处理器对
`HTTPException` / `RequestValidationError` 都不生效**——Starlette 按 `type(exc).__mro__`
顺序查找，更具体的 handler（FastAPI 内置的 `http_exception_handler` /
`request_validation_exception_handler`）优先命中，因此这两类错误仍返回 FastAPI 标准
`{"detail": ...}` 格式，而不是 `code/info/data` 包装。写客户端解析逻辑时需区分两种形态。
（此前那次 `msg=` → `info=` 的修复本身仍然正确，只是覆盖范围比预期小。）

### 探测脚本注意
用 TestClient 探测 WS 时，若构造的数据不满足服务端发消息条件（如 `reg_spks` 非空
但 `last_vad_beg <= 1` 导致无 `code=0`），`receive_json()` 会**永久阻塞**；
且进程被 kill 后管道缓冲的 stdout 会全部丢失。正确做法：结果**边跑边写文件**，
并用 `threading.Thread(daemon=True) + join(timeout)` 包住，超时即放弃。
